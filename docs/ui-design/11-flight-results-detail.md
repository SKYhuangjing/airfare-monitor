# 候选航班详情页设计说明

## 使用场景

用户在概览看到最低价后，需要确认其他航班是否在时间、直达性、中转等待、行李或余票方面更合适。该页面是“监控结果解释与比较”页面，不是购票页面。

## 页面结构

1. 顶部：返回我的航程、中文起止地点与 IATA、日期、来源、“完整响应”状态。
2. 结果摘要：最低含税总价、合格候选总数/本地展示数、直达/中转数量、查询时间。
3. 本地筛选条：航班/航司搜索、排序、直达性、起飞时段、低于心理价位。
4. 候选表：对比选择、排名/航班、起降时刻与机场、行程、含税总价、票价/税费/行李/余票、返程摘要；相关字段合并为七列以适配主窗口宽度。
5. 底部对比条：显示已选数量；选择 2～3 个时可打开横向对比。

## 状态规则

- 尚无完整结果：解释需要先执行一次查询，不展示假数据。
- 最近查询失败：继续展示上一次完整结果，并在表格上方给出明确提示。
- 候选超过 200：摘要显示合格总数和保存数，说明当前展示价格最低的前 200 条。
- 平台字段缺失：显示“未提供”，不推断行李、余票或税费。
- 往返：一行代表一个去返程组合价，返程列展示返程航班和时刻。
- 对比只发生在同一轮查询内，最多 3 个候选。

## 产品边界

- 打开、筛选、排序和对比均只读本地 SQLite，不触发新查询。
- 所有价格使用解析后的 CNY 含税总价。
- 不展示购买按钮，不登录，不预订，不支付，不绕过验证码或设备验证。
