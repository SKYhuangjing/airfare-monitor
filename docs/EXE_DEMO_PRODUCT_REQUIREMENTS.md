> 本文只定义产品与技术方案，不包含代码实现。当前采集、解析、存储、Excel 和邮件能力作为已有业务内核复用。

## 1. 决策摘要

1. 产品形态采用 Windows 桌面托盘应用，交付物为 `AirfareMonitorSetup.exe` 安装器。用户安装后从桌面或开始菜单启动，不接触 Python、PowerShell、YAML 或 `.env`。
2. 产品名确定为“航价守望”。核心体验是“选择出发地和目的地 → 选择日期和偏好 → 点击开始监控 → 在首页看最低价和状态”。
3. 中国大陆境内航线继续使用同程旅行；任一端不属于中国大陆的跨境、港澳台和国际航线继续使用去哪儿。
4. 地点选择采用“内置、版本化的机场目录”，每个选项直接映射当前代码已有的真实机场 IATA 和中文地点名；演示版运行时不依赖去哪儿或同程的地点联想接口。
5. 普通用户通过中文、拼音搜索地点。单机场城市可只显示城市名；多机场城市显示具体机场，例如“北京首都”“北京大兴”“上海虹桥”“上海浦东”。
6. P0 不支持 `BJS/NYC/LON/TYO` 等全机场城市集合代码，不新增城市数据模型；查询结果继续展示实际起降机场三字码。
7. 验证码或设备验证只能提示用户人工处理，产品不得实现验证码绕过、设备挑战绕过、自动登录、预订或支付。
8. P0 同时支持桌面通知和用户自行配置的 SMTP 邮件，并提供测试邮件通路。
9. P0 使用电脑已有 Chrome/Edge；允许通过覆盖安装升级；暂不购买代码签名证书。
10. 首批试用人数为 5 人；地点清单后续补充，可先通过隔离浏览器自动化观察和人工审核形成机场目录种子数据。
11. 已授权在开发和验收阶段各执行代表性的国内、国际单程和国际往返真实集成查询，但每次运行仍应明确标识为集成测试。
12. 演示版优先证明易用性和完整闭环，不追求多用户、云端管理、自动升级和所有机场覆盖。
13. 每台设备最多同时启用 10 个监控航程；始终使用一个隔离浏览器串行查询，不通过并发扩大采集量。
14. 前端提供浏览器显示模式控制，用户可选择可见运行或后台隐藏运行。

## 2. 背景与现状

### 2.1 已有能力

当前代码已经具备：

- 多航程配置和启停；
- 中国大陆境内/跨境国际的来源自动选择；
- 去哪儿国际单程、国际往返组合价采集；
- 同程国内单程直达采集；
- 去返程起飞时间窗；
- 直达/允许中转及最长中转等待时间；
- 心理价位、低价二次确认；
- 重点关注班次及首次价、上次价对比；
- 完整响应校验；
- CNY 含税总价排序和告警；
- SQLite 历史记录；
- Excel 报告和合并邮件；
- 单程失败重试、连续失败重启浏览器、进程锁；
- 验证码和设备验证的人工处理状态。

### 2.2 当前使用门槛

当前使用者必须自行安装 Python、创建虚拟环境、编辑 YAML/环境变量、配置 SMTP、启动守护命令并管理 Windows 任务计划。演示版需要把这些操作全部封装起来。

### 2.3 当前能力边界

- 国内航班：同程，仅支持单程直达。
- 国际/跨境航班：去哪儿，支持单程和往返组合价；支持直达或中转。
- 所有航程串行查询。
- 只有最终完整响应才算成功。
- 价格是查询时刻的观察价格，不代表最终可售价格。
- 软件不登录、不下单、不支付、不绕过验证。

## 3. 产品目标

### 3.1 目标

- 同事在一台符合条件的 Windows 电脑上，安装后 5 分钟内完成首次配置。
- 不阅读说明书的用户可在 2 分钟内添加一个航程。
- 常规操作中不出现 IATA、SMTP、端口、Profile、YAML、数据库等技术概念。
- 用户能够清楚看到软件是否正在运行、上次是否成功、下次何时查询。
- 用户能从首页直接看到每个航程的最新最低含税总价、心理价差和趋势。
- 出现网络、页面改版、浏览器缺失或人工验证时，提供可执行的中文提示。
- 关闭主窗口后可继续在系统托盘运行；明确“退出软件会停止监控”。
- 将产品约束为个人、小规模、低频监控工具，不提供批量导入百条航线、并发浏览器或高频采集能力。

### 3.2 演示成功标准

一次完整演示应能够做到：

1. 双击安装器并完成安装；
2. 首次启动自动检测浏览器和本地目录；
3. 通过中文搜索选择起运地和目的地；
4. 添加一个国内航程和一个国际航程；
5. 在 UI 中校验配置并启动一次查询；
6. 显示查询中、成功、部分成功或需要人工处理状态；
7. 展示最低价、价格变化、重点班次和 Excel；
8. 可选择发送测试邮件；
9. 最小化到托盘后继续运行；
10. 重启应用后配置和历史仍存在。

### 3.3 非目标

- 不做机票预订、跳转下单闭环或支付。
- 不保存网站账号密码，不做自动账号登录。
- 不做验证码识别、自动点击或设备挑战绕过。
- 不做云端账号、多租户、组织权限或管理员后台。
- 不做 macOS、Linux 或移动端。
- 不保证覆盖世界全部机场和全部多机场城市。
- 不承诺第三方网站永久不变或 100% 无人值守。
- 不允许单台设备同时启用超过 10 个航程，不通过多窗口、多进程或多浏览器绕开限制。

## 4. 用户与核心场景

### 4.1 主要用户

普通公司同事：懂得出发城市、目的城市、日期和预算，但不了解机场代码、浏览器自动化和邮件服务器配置。

### 4.2 核心场景

- 出差：关注固定日期、固定时段的最低含税价。
- 个人旅行：关注未来日期的国内或国际单程。
- 国际旅行：关注平台提供的往返组合总价。
- 指定班次：关注某个目标起降时间附近的航班价格。
- 低价提醒：价格低于心理价位后二次确认并提醒。
- 异常恢复：网站要求人工确认时，从软件打开独立验证页面并恢复查询。

## 5. 产品信息架构

左侧导航保持五个一级入口：

1. 概览
2. 我的航程
3. 历史价格
4. 通知设置
5. 系统状态

系统托盘菜单提供：

- 打开航价守望
- 立即查询
- 暂停/继续监控
- 打开最新报告
- 退出并停止监控

## 6. 核心用户流程

```text
安装 EXE
  → 首次启动检查
  → 添加航程
  → 配置价格与班次
  → 确认并开始监控
  → 首页查看状态与结果
  → 低价提醒 / 人工处理 / 打开报告
```

## 7. 页面需求

### 7.1 首次启动

#### 页面内容

- 欢迎文案和一句话产品说明；
- 自动检测 Chrome、Edge 或兼容 Chromium；
- 自动创建独立浏览器数据目录；
- 检测本地数据目录是否可写；
- 选择是否开机自动启动；
- 选择默认查询间隔：30 分钟、60 分钟、120 分钟；
- 选择浏览器运行方式：“显示运行过程”或“后台隐藏运行”；
- 通知方式：桌面通知默认开启；邮件通知保留，用户可在此配置或稍后配置；
- “开始添加航程”主按钮。

#### 浏览器策略

- P0 自动发现电脑已有的 Chrome/Edge，并使用软件自己的独立 Profile；
- 绝不复用用户日常浏览器 Profile；
- 未发现兼容浏览器时给出安装指引，不静默失败；
- 独立 Profile 建议位于 `%LOCALAPPDATA%/AirfareMonitor/data/browser-profile/`；
- P0 不随安装包内置 Chromium；若 Chrome 和 Edge 同时存在，允许用户在高级设置中切换。

#### 浏览器显示模式

- 在“系统状态/浏览器设置”提供全局开关“显示浏览器运行过程”；
- 开启时映射为 `browser.headless: false`，查询期间显示独立浏览器窗口；
- 关闭时映射为 `browser.headless: true`，查询在后台执行；
- 首次安装默认开启，方便用户观察和排查；用户确认运行正常后可主动关闭；
- 修改模式时，如果当前没有查询任务，安全重启独立浏览器后立即生效；如果正在查询，则提示“将在本轮结束后生效”；
- 可见模式下提示用户不要手工关闭自动化浏览器；意外关闭时由应用恢复并记录本轮失败；
- 隐藏模式出现验证码或设备验证时，“打开验证页面”必须临时以可见模式打开同一个隔离 Profile；处理完成后恢复用户原有模式；
- 无论可见或隐藏，都不得使用用户日常浏览器 Profile。

### 7.2 概览首页

与已生成 UI 稿保持一致，包含：

- 监控运行中/已暂停/需要处理；
- 下次查询时间；
- 今日最低价、监控航程数、最近成功时间、需要处理数量；
- 每个航程的当前最低含税总价、心理价差、价格趋势和更新时间；
- “添加航程”“立即查询”；
- 最近动态；
- 异常航程的“去处理”入口。

#### 状态语义

- 绿色：查询完成且结果有效；
- 蓝色：查询进行中或普通信息；
- 橙色：需要用户确认、部分失败或配置待处理；
- 红色：程序无法启动、配置损坏或连续运行失败。

### 7.3 我的航程

#### 列表能力

- 新增、编辑、复制、启用、暂停、删除航程；
- 显示来源标签：“国内 · 同程”或“国际/跨境 · 去哪儿”；
- 显示单程/往返、日期、时间窗、直达偏好、心理价位；
- 显示最近一次查询状态；
- 删除前二次确认；
- 暂停不删除历史。

#### 每台设备监控数量限制

- 同一设备最多同时启用 10 个航程；单程和往返均按一个航程计数；
- 已暂停、仅保存未启用的航程不占用 10 条额度；
- 达到 10 条后仍可保存新航程，但“保存并开始监控”不可用，只能保存为暂停状态；
- 启用第 11 条时提示“当前设备最多同时监控 10 个航程，请先暂停一个现有航程”，并提供航程列表入口；
- 复制航程默认保存为暂停状态，避免无意增加查询量；
- 概览和“我的航程”显示“已启用 7/10”等容量信息；
- P0 不提供批量导入、批量启用或修改配置文件绕开上限的产品入口；
- 应用启动和读取旧配置时也必须校验上限。若旧配置已有超过 10 条启用航程，保留原数据但暂不启动监控，要求用户明确选择需要暂停的航程，避免软件擅自改变配置。

### 7.4 添加/编辑航程向导

向导分三步，避免在一个页面暴露全部高级字段。

#### 第一步：航程信息

- 从哪里出发：中文地点搜索选择器；
- 到哪里：中文地点搜索选择器；
- 交换起止地点；
- 单程/往返；
- 出发日期；
- 返程日期，仅往返显示；
- 起飞时段预设：全天、上午、下午、晚上、自定义；
- 返程起飞时段，仅往返显示；
- 右侧显示实时“监控预览”。

P0 不改变当前代码的一机场一码模型。单机场城市可显示“吉隆坡”；多机场城市显示具体选项，例如“上海虹桥”“上海浦东”“北京首都”“北京大兴”。用户无需手工输入 IATA，但选中后界面可以用弱化文字显示三字码。结果页、邮件和 Excel 展示实际航班的起降机场三字码，例如 `PVG → KUL`。

#### 第二步：价格与班次

- 行程偏好：仅直达/允许中转；
- 最长中转等待时间，仅在来源和行程类型支持时显示；
- 心理价位，可为空；
- 重点关注班次，可选；
- 成人数默认 1，儿童数默认 0，放入高级设置；
- 舱位默认经济舱，放入高级设置；
- 通知、邮件和 Excel 的最低价候选数量固定为 10，不在普通表单暴露；同一轮完整响应可另行保留最多 200 条合格候选供桌面端查看。

#### 第三步：确认

- 中文总结起点、终点、日期、时间、价格条件；
- 明确显示实际查询来源；
- 对当前不支持的组合给出阻止性说明；
- “保存并开始监控”；
- “保存但暂不启动”。

#### 能力联动规则

| 条件 | UI 行为 |
| --- | --- |
| 两个机场均属于中国大陆 | 自动显示“国内 · 同程” |
| 任一机场属于港澳台或境外 | 自动显示“国际/跨境 · 去哪儿” |
| 国内航线 | P0 仅允许单程、仅直达 |
| 国内选择往返 | 禁用并提示“当前版本暂不支持国内往返组合价”；引导用户另建一条起终点相反的单程航程，单独选择返程日期、监控返程价格，两条航程各占一个名额 |
| 国内选择允许中转 | 禁用并提示“当前版本国内航线仅支持直达” |
| 国际/跨境航线 | 允许单程/往返、直达/中转 |
| 心理价位为空 | 只观察价格，不触发低价命中 |
| 往返 | 心理价位表示去返程组合含税总价 |

### 7.5 候选航班详情与对比

用户可从概览或“我的航程”进入最近一轮候选详情，用于在看到最低价后比较其他更合适的航班：

- 只读取该航程最近一次成功且完整的查询结果，不为打开页面额外访问去哪儿或同程；
- 展示当前航程日期、时段、直达/中转等设置范围内的候选，最多保留价格排序前 200 条；
- 展示航班号、实际起降机场三字码、起降时间、跨日、总耗时、直达/中转机场和等待时间、基础票价、税费、CNY 含税总价、行李和余票信息；平台未提供的字段明确显示“未提供”；
- 支持按航班号或航司代码搜索，按直达/中转、起飞时段和心理价位筛选，并按价格、起飞、到达或总耗时排序；
- 可选择 2～3 个候选做同轮横向对比；不提供登录、预订、支付或跳转购买能力；
- 如果最近一次查询失败，明确提示当前展示的是上一次完整结果；如果合格候选超过保存上限，展示总数与实际保存数；
- 通知、邮件和 Excel 仍只使用最低价前 10 条，避免改变既有提醒和报告语义。

扩展候选仅保留最近 7 天；每轮前 10 条继续作为价格历史保留，不因候选详情清理而删除。

### 7.6 历史价格

P0 提供轻量历史视图：

- 按航程切换；
- 最近 24 小时/7 天价格曲线；
- 最低、最高、当前价格；
- 标记心理价位线；
- 标记采集失败或无匹配航班的时间点；
- 打开最新 Excel；
- 打开报告目录。

### 7.7 通知设置

#### 桌面通知

- 默认开启；
- 通知低价命中、部分失败、需要人工处理；
- 普通成功轮次默认不弹窗，避免打扰。

#### 邮件通知

- 可选启用；
- 每位用户自行配置自己的 SMTP，不依赖公司统一通知通道；
- 表单字段：SMTP 服务、端口、安全方式、账号、授权码、发件人、收件人；
- 提供常见邮箱配置说明链接，但不把网页登录密码称为授权码；
- “发送测试邮件”；
- 测试邮件成功后显示服务器连接、身份验证和投递请求均已完成；失败时只显示可操作原因，不回显授权码；
- 授权码保存至 Windows 凭据安全存储，不明文显示、不写入仓库；
- 支持关闭附件；
- 邮件失败不影响采集结果保存。

### 7.8 系统状态与人工处理

与已生成 UI 稿保持一致：

- 监控服务、数据存储、航班查询三项健康状态；
- 显示当前浏览器类型、运行模式和“显示浏览器运行过程”开关；
- 出现验证码或设备验证时说明原因和受影响航程；
- “打开验证页面”；
- “我已完成，重新查询”；
- “稍后处理”；
- 其他航程是否仍正常；
- 最近运行记录；
- 导出脱敏诊断信息。

诊断信息不得包含 SMTP 授权码、Cookie、浏览器 Token、个人邮箱全文或完整原始响应中的敏感字段。

## 8. 地点数据方案

### 8.1 问题定义

当前代码同时需要：

- 三字母真实机场 IATA，用于当前配置、来源判断、搜索和结果校验；
- 官网认可的中文城市/地点名，用于同程结果页 URL 和去哪儿国际往返 URL；
- 面向普通用户的中文名称、英文名、拼音和别名，用于本地搜索。

现有 `airportsdata` 本地依赖可提供大量真实机场的 IATA、国家、英文城市、经纬度和时区，但不提供平台需要的中文地点名。因此 P0 只需在它之上补充一层中文机场目录，不改变当前航程模型。

### 8.2 方案比较

| 方案 | 优点 | 缺点 | P0 决策 |
| --- | --- | --- | --- |
| 每次输入实时调用官网联想 | 地点新、与平台同步 | 私有接口易变；依赖网络；可能触发验证；两平台结构不同；输入体验不稳定 | 不采用 |
| 完全手工写死少量机场 | 简单、可靠 | 覆盖不足、维护困难 | 仅作为最小种子数据 |
| 内置版本化机场目录 | 快、稳定、离线可搜索、可直接生成当前配置 | 需要维护中文名和可用性 | 采用 |
| 本地目录＋后台下载自有更新包 | 兼顾稳定和更新 | 需要目录发布服务和签名校验 | P1 |

### 8.3 最终建议

P0 使用“内置机场目录＋自动化观察候选＋人工审核”的方案：

1. 以 `airportsdata` 提供机场基础字段和国家归属；
2. 项目只补充中文显示名、官网查询中文名、拼音别名和来源可用性；
3. 每条目录记录必须对应一个当前代码可接受的真实机场 IATA；
4. 机场目录随安装包发布并带版本号；
5. P0 不在用户输入时请求官网地点接口；
6. 可在开发阶段使用隔离浏览器自动化输入机场中文名、拼音或 IATA，只读观察去哪儿/同程联想数据，批量生成候选；候选未经人工审核不得进入正式目录；
7. 第一次真实查询同时充当最终可用性验证，失败时给出机场名称校准提示；
8. 后续可增加“机场目录更新包”，但不把官网私有联想接口作为产品运行依赖。

### 8.4 机场目录数据模型

每个选项保持轻量，仅包含：

| 字段 | 含义 |
| --- | --- |
| `airport_iata` | 真实机场 IATA，也是当前代码使用的起止代码 |
| `display_name_zh` | UI 中文显示名，如“上海浦东” |
| `city_name_zh` | 当前 `origin_name_zh/destination_name_zh` 使用的官网中文地点名，如“上海” |
| `airport_name_zh` | 完整机场中文名，可选 |
| `display_name_en` | 英文城市/机场名，可选 |
| `country_code` | ISO 国家/地区代码 |
| `aliases` | 中文简称、英文、拼音、拼音首字母、旧称 |
| `supported_sources` | 可用于去哪儿、同程或两者 |
| `verified_at` | 最近人工验证日期 |
| `catalog_version` | 机场目录版本 |
| `enabled` | 是否允许普通用户选择 |

目录记录选中后直接生成当前已有字段：

```text
origin_airport_iata / destination_airport_iata
origin_name_zh / destination_name_zh
market: auto
```

### 8.5 机场、城市集合与航司代码

- `PVG`、`SHA`、`PEK`、`PKX`、`NRT`、`JFK` 是机场 IATA，可进入 P0 目录；
- `BJS`、`TYO`、`NYC`、`LON` 等城市集合代码不进入 P0，避免修改当前模型和来源判断；
- 航司代码是另一个概念，任何地点字段都不得接受航司代码；
- 机场 IATA 在下拉选项中可以弱化显示，但保存前必须由目录提供，用户不能任意填写；
- 结果中的实际起降机场继续按现有解析逻辑保存和展示。

### 8.6 P0 选择与展示规则

1. 单机场城市可用城市名简化展示，例如“吉隆坡”，详情弱化显示 `KUL`；
2. 多机场城市必须拆成具体选项，例如“上海虹桥 SHA”“上海浦东 PVG”；
3. 已生成 UI 稿中的“上海（全部机场）”修改为具体机场选择器，不实现全机场聚合；
4. 输入“上海”时同时返回虹桥和浦东，输入“北京”时同时返回首都和大兴；
5. 支持中文、英文、拼音、拼音首字母和 IATA 搜索；
6. 结果页、桌面通知、邮件和 Excel 展示实际机场三字码；
7. 重点班次沿用当前能力，可在高级设置中指定实际机场。

### 8.7 P0 地点覆盖范围

“所有热门地点”必须变成可验收的清单。首批试用人数已确定为 5 人，完整必选清单由用户后续提供。建议首版约 200 条机场记录：

- 中国大陆约 80 个主要客运机场；
- 港澳台、东亚、东南亚约 60 个常用机场；
- 欧洲、北美、大洋洲、中东约 60 个常用机场；
- 必须覆盖 5 名试用同事明确提出的全部起止机场。

首版排序依据：

1. 试用用户实际需求；
2. 官网公开的热门城市；
3. 国内省会、计划单列市、主要商务和旅游城市；
4. 中国出境常用枢纽和主要旅游目的地；
5. 对应来源实际查询验证通过。

不在目录内时：

- 普通用户看到“当前地点库暂未收录，可提交补充”；
- P0 不允许自由输入未知字符串直接保存；
- 维护者通过独立的机场校准流程补充后随目录版本发布；
- 不要求普通同事从官网复制名称或代码。

### 8.8 机场目录获取与校准流程

机场目录维护属于开发/运营流程，不进入普通用户产品：

1. 在项目隔离 Chromium Profile 中打开去哪儿或同程公开机票入口；
2. 自动或人工输入目标机场的中文、拼音或 IATA；
3. 只读观察页面联想结果，记录平台认可的中文名和代码；
4. 不登录、不下单、不绕过验证；
5. 只保留能够映射到真实机场 IATA 的候选；
6. 用一条公开搜索链路验证起点、终点和结果实际机场一致；
7. 审核后提升目录版本。

首批目录可先从官网公开热门城市、`airportsdata` 和用户必选清单生成候选，再用自动化逐条观察联想结果。演示版开发开始前，建议验证：

- 单机场国内城市；
- 多机场国内城市；
- 单机场国际城市；
- 多机场国际城市；
- 港澳台地点；
- 机场名称和城市名称不同的地点。

## 9. 查询来源与运行规则

### 9.1 来源路由

| 起点 | 终点 | 来源 |
| --- | --- | --- |
| 中国大陆 | 中国大陆 | 同程 |
| 中国大陆 | 港澳台/境外 | 去哪儿 |
| 港澳台/境外 | 中国大陆 | 去哪儿 |
| 港澳台/境外 | 港澳台/境外 | 去哪儿 |

用户不需要手工选择来源。高级诊断可以显示来源，但普通表单只显示自动判断结果。

### 9.2 完成条件

- 去哪儿只有观察到 `result.ctrlInfo.completed == true` 才能标记成功；
- 同程只有最终页面状态完成、航线日期一致并且列表结构有效时才能标记成功；
- 不完整响应不得入库为成功，不得触发低价提醒；
- 同程价格必须使用票面价＋机建燃油后的预计支付总价；
- 往返必须使用平台返回的完整组合总价，不得把两个单程最低价相加。

### 9.3 调度

- P0 采用全局查询间隔，不做每条航程独立调度；
- 默认 30 分钟，可选 60/120 分钟；
- 最短查询间隔为 30 分钟，P0 不开放更高频设置；
- 每台设备最多同时启用 10 个航程；
- 启动监控后立即执行一次；
- 始终复用一个隔离浏览器并串行执行，禁止并发查询多个航程；
- 上一轮未完成时不得开启重叠轮次；
- 如果一轮运行超过设定间隔，下一轮不得立刻连续启动；从上一轮结束后至少冷却 5 分钟，再按抖动策略安排下一轮；
- 首页显示上一轮总耗时；若连续两轮耗时接近或超过间隔，提示用户减少航程或延长间隔；
- 电脑休眠期间不保证执行，唤醒后恢复并显示错过状态；
- 修改航程后由应用安全重载，不要求用户重启守护命令。

## 11. 数据、文件与安全

- 用户配置、数据库、Excel、日志、独立浏览器 Profile 均保存在当前用户的本地应用数据目录；
- 不把用户数据写入安装目录；
- SMTP 授权码使用 Windows 凭据安全存储；
- 日志不得记录 SMTP 密码、Cookie、Token 或个人邮箱全文；
- 原始响应默认保留 7 天；
- 日志按大小和日期轮转；
- Excel 提供保留期限设置，默认 30 天；
- 数据库升级必须包含版本和迁移；
- 卸载时默认保留用户数据，并提供“同时删除本地数据”的明确选项；
- 导出诊断信息必须先脱敏；
- 禁止复用用户日常 Chrome Profile。

## 12. EXE、安装与运行形态

### 12.1 交付方式

推荐交付一个安装器 EXE，而不是一个真正的单文件便携程序：

- 安装器创建开始菜单和桌面入口；
- 安装 Python 运行时和项目依赖，用户不可见；
- 创建本地数据目录；
- 注册卸载项；
- 可选注册当前用户登录时启动；
- 安装升级不覆盖用户数据；
- 应用版本在“系统状态”中可见。

### 12.2 单实例与关闭行为

- 重复启动时激活已有窗口；
- 关闭窗口默认最小化到托盘；
- 托盘“退出并停止监控”才真正停止；
- 系统退出和应用崩溃时正常释放浏览器进程与运行锁；
- 崩溃后下次启动提示上次异常结束。

### 12.3 P0 更新策略

- P0 确定采用人工安装新版本覆盖升级；
- 升级必须保留配置、数据库和凭据；
- 自动更新和发布通道列入 P1；
- P0 面向 5 名内部试用用户，暂不购买代码签名证书；安装说明需明确内部来源和文件校验方式；
- 如果后续扩大分发范围，再评估代码签名。

## 13. 错误与恢复设计

| 错误 | 用户文案方向 | 操作 |
| --- | --- | --- |
| 未发现浏览器 | “需要安装 Chrome 或 Edge 才能查询” | 打开安装说明/重新检测 |
| 启用航程达到 10 条 | “当前设备最多同时监控 10 个航程” | 暂停一个现有航程 |
| 可见浏览器被手工关闭 | “自动化浏览器被关闭，本轮将重新启动后重试” | 立即重试/稍后处理 |
| 地点未收录 | “当前地点库暂未收录” | 提交补充 |
| 平台不识别地点 | “该地点暂时无法在当前来源查询” | 更换具体机场/提交校准 |
| 网络不可用 | “网络连接失败，本轮稍后重试” | 立即重试 |
| 完整响应超时 | “网站返回尚未完成，本轮未采用该价格” | 重试/查看状态 |
| 验证码或设备验证 | “需要你完成一次页面确认” | 打开验证页面/完成后重试 |
| 页面结构变化 | “查询页面可能已更新” | 导出诊断信息 |
| SMTP 失败 | “价格已保存，但邮件发送失败” | 测试邮件/检查配置 |
| 重复进程 | 自动激活原窗口 | 无需用户处理 |

任何异常都不得把基础票价误当作含税总价，也不得把未完成结果标记为成功。

## 15. 验收标准

### 15.1 易用性

- 用户无需安装 Python、打开命令行或编辑配置文件；
- 中文、拼音、拼音首字母或 IATA 均可搜索已收录机场；
- 普通页面不暴露技术配置；
- 无效或不支持组合不能被保存；
- 达到 10 个启用航程后不能启用第 11 个；暂停一个后可再启用；
- 首次新增航程中位完成时间目标不超过 2 分钟。

### 15.2 功能

- 中国大陆境内航线选择同程；跨境/国际选择去哪儿；
- 单机场城市可简化显示城市名；多机场城市选择具体机场；
- 航班结果展示实际起降机场三字码；
- 完整响应规则与当前内核一致；
- 排序、历史和阈值均使用 CNY 含税总价；
- 低价命中进行二次确认；
- 邮件失败不丢失数据库和 Excel；
- 桌面通知和邮件可以独立开关；每位用户可完成 SMTP 测试通路；
- 重启应用后航程、历史和通知设置仍存在；
- 不允许两个调度进程重叠。
- 航程严格串行执行，不允许并发查询；超时轮次结束后至少冷却 5 分钟；
- 浏览器显示开关正确映射 `headless`，并在安全重启浏览器后生效；
- 隐藏模式出现人工验证时可以临时打开可见的隔离浏览器，完成后恢复原设置。

### 15.3 安全

- 浏览器使用独立 Profile；
- 安装包和日志不包含个人邮箱或密码；
- SMTP 授权码不写入普通配置文件；
- 不实现登录、下单、支付或验证码绕过；
- 导出的诊断包通过敏感信息扫描。

### 15.4 测试

- 现有离线测试继续全部通过；
- 新增 UI 配置映射、机场目录、安装升级、单实例和凭据测试；
- 本项目已获得一次代表性国内、国际单程和国际往返真实集成查询授权；测试仍必须由明确标识的集成入口触发；
- 真实集成测试不得发送邮件或复用日常浏览器 Profile；
- 发布前分别验证一个国内航程、一个国际单程和一个国际往返。
