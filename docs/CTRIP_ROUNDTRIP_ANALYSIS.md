# 携程往返 HAR 分析与真实页面验证

分析日期：2026-10-12。本文记录接入前的协议分析和真实页面探测。随后已按官网原生“往返组合”模式完成产品接入与两项正式采集器实站验证，当前源码的国际往返默认使用携程；最新结果见[迁移与验收记录](CTRIP_MIGRATION.md)。

## 用户录制的内容

录制查询为上海→吉隆坡，2026-10-14 去、2026-10-17 返，1 成人、经济/超经舱搜索。页面路径为 `/online/list/round-sha-kul0`，`depdate` 使用 `2026-10-14_2026-10-17`。

HAR 共 445 条网络记录，其中 12 条是搜索请求。搜索继续使用 `/international/search/api/search/batchSearch` 和 `/international/search/api/search/pull/…`。往返请求的 `flightWay` 为 `D`，包含两项 `flightSegments`，分别指定去、返程城市及日期。

本份 HAR 的搜索请求均为 `segmentNo=1`，属于默认“自由搭配”的去程选择阶段。两个关键响应声明大小分别为 30,090,033 与 30,120,247 字节，但 HAR 的 `response.content` 中均没有 `text`，无法直接离线还原报价和最终完成状态。这是响应正文缺失，而非读取 JSON 失败。

辅助行李/签证请求包含同一组合去、返程航段和 `TotalPrice`，可作为流程旁证，但不能替代搜索完成响应，不能作为采集成功依据。

## 真实页面验证

沿用用户先前明确授权的真实网站联调，使用项目独立浏览器 Profile；没有登录、预订、支付、验证绕过、API 请求重放或邮件发送。

默认“自由搭配”模式的完成响应只有去程行程，报价为往返起价。一轮实际观察到 80 个去程候选、4,087 个报价，另一轮因实时变化为 81 个候选、4,165 个报价，顶层 `flightSegments` 均仅有 `segmentNo=1`。正常点击“选为去程”后另有 `segmentNo=2` 的返程请求；该响应未提供与首轮相同的完成标记，不能直接按单程轮询规则认定完成。该模式需要额外维护选择状态及组合关联。

录制中包含的官网脚本显示，“往返组合”开关将页面参数设为 `isbuildup=1`，并使用 `segmentNo=0` 的完整往返查询。真实打开同一公开查询页面并启用该模式后，得到以下结果：

| 项目 | 实测结果 |
|---|---|
| 观测时间 | 2026-10-12 14:46，北京时间 |
| 查询 | 上海→吉隆坡，10-14 去、10-17 返，1 成人 |
| 中间非空列表 | 473 条，`finished=false` |
| 最终列表 | 1,292 条，`finished=true`、HTTP 200、业务状态 0 |
| 最终报价 | 3,871 个 |
| 行程方向 | 全部包含 `segmentNo=1` 和 `segmentNo=2` 两个方向 |
| 初步最低含税总价 | 1,903 元 = 基础票价 510 + 税费 1,393 |
| 最低价组合之一 | 去程 CX303/CX729，返程 CX722/CX302 |

最低价计算按实际 PVG/KUL 机场及普通经济舱报价初步筛选，属于分析结果，尚非产品往返采集器的验收结果。上述价格与数量随实时查询变化。

最终组合价中的 `adultPrice`、`adultTax` 已是去返程合计，不能分别给两个方向重复计价。每个方向的航班、实际机场、日期、起降时间和平台耗时均可从该组合的两个 `flightSegments` 中取得。

## 对现有代码的影响

无需重写桌面、存储和 Excel：项目已有去哪儿往返实现，`ItinerarySnapshot`、`return_itinerary`、返程规则与往返展示均可复用。采集监听、完成标记、价格计算和大部分单程解析逻辑也可沿用。

后续接入已完成以下工作：

1. 携程往返查询 URL 使用双日期及 `isbuildup=1`；搜索关联同时检查两个方向、返程日期和 `segmentNo=0`，不能接收默认自由搭配的阶段结果。
2. 解析完整两个方向，分别执行实际机场、日期、时间窗、直飞及中转限制；将返程保存到 `return_itinerary`。
3. 以去程和返程全部航段生成组合签名，避免同一去程搭配不同返程被错误合并。每个组合的含税价只计算一次，再按全体乘客人数汇总。
4. 提高浏览器网络监听的响应缓存容量。实测默认配置无法取得约 30 MB 正文；在监听所在 CDP 会话设置总缓存 128 MiB、单响应缓存 64 MiB 后成功获取。正式接入需封装这一依赖并验证大响应的读取失败提示。
5. 扩展自动来源路由及界面能力提示，新增脱敏往返样本、离线回归和真实页面验证，确认 Top N、候选保存上限、重点班次和历史比较行为。

这是现有携程适配器的扩展，不需要新增数据库 schema。已增加多人、两方向独立筛选、组合去重、历史基准和导出验证；更多航线及高端舱位往返仍需扩大覆盖。

## 本次修复与边界

真实大页面加载期间，DrissionPage 可能返回表示未找到元素的 `NoneElement`；其值为假，但对象并非 Python `None`。原有验证检查继续读取其 `.text` 会抛异常。本次已改为判断元素真值，并增加回归测试。完整离线测试集 137 项通过，未发起额外离线测试网络请求或邮件发送。

原始 HAR 留在仓库外；探测产物只保留字段白名单和类型结构，不保存搜索凭据或原始响应。脱敏数据、截图及分析摘要位于被 Git 忽略的 `outputs/ctrip-roundtrip-combo-probe/`。正式接入后的两项往返联调产物位于 `outputs/ctrip-live-test/`，不改写用户正式监控数据库。
